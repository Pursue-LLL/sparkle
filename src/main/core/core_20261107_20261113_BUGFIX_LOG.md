## 五、踩坑清单（给后来的人）

1. **日志是旁路，必须尽力而为**：`appendAppLog` 有 133 处调用方，它的失败不能改变业务流程（详见 utils 日志）。
2. **孤立的测试等于没有测试**：25 个测试文件曾不在 `test:node-quality` 里，其中一个 5 / 7 失败却没人知道（详见 scripts 日志）。
3. **测量脚本必须核对退出码与产物时间**：一次覆盖率测量因脚本没有执行权限而静默沿用了旧数据，靠核对时间戳才发现。
4. **变异测试的价值是逼出「没有任何测试能区分的代码」**：补测试、删冗余、确认等价三选一，不接受「看起来没问题」。
5. **依赖文件系统事件的测试要让「事件丢失」不影响结论**，不能赌一次事件。
6. **解析别人的格式，要按对方的真实布局写，并用对方做差分**：`ruleSyntax` 最初按「策略是最后一个非 `no-resolve` 字段」猜，直到用真实内核核对才发现 `src` 等参数。
7. **带真实 `sleep` 的断言在负载下会误报**：时间相关的用例用 mock 定时器推进（`probeWarmupCore.test.ts` 曾在整套测试里失败过一次）。
8. **修一个缺口会暴露下一个缺口**：MATCH 兜底暴露国内直连、补 `DIRECT` 引入 #8；兜底、补默认值类修复必须同时回答「兜底后谁受伤」。
9. **重写历史后，日志与构建标记里的旧哈希会失效**：写文档只引用改写后的哈希，并保留「提交主题」作为定位手段。
